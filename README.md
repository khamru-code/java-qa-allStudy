# Java QA — мой путь в автоматизацию тестирования

Привет! Меня зовут Руслан.

Несколько лет я работаю программистом 1С, но сейчас решил развиваться в новом направлении — автоматизации тестирования на Java.

Этот репозиторий создан для хранения всех практических заданий, примеров и небольших проектов, которые я выполняю во время обучения.

Здесь можно увидеть не только итоговый код, но и мой постепенный путь: от основ Java до написания UI-автотестов с использованием Selenide и JUnit 5.

## Цель репозитория

Основные цели этого проекта:

- фиксировать мой прогресс в изучении Java и автоматизации тестирования;
- сохранять выполненные задания и примеры;
- учиться работать с Git и GitHub;
- постепенно улучшать структуру и качество автотестов;
- получать обратную связь от более опытных QA-инженеров;
- собрать учебное портфолио для дальнейшего поиска работы в AQA.

## Что уже изучается в проекте

### Основы Java

В репозитории есть примеры работы с:

- переменными и типами данных;
- математическими, логическими операторами и операторами сравнения;
- условиями `if`, `else` и `switch`;
- циклами `for` и `foreach`;
- массивами;
- методами;
- классами и объектами;
- конструкторами;
- коллекциями `List`, `Set` и `Map`;
- `boxing` и `unboxing`;
- перечислениями `enum`;
- потоками `Stream`;
- рефлексией.

### JUnit 5

В процессе обучения используются:

- аннотации `@Test`;
- `@BeforeAll` и `@BeforeEach`;
- проверки через `Assertions`;
- параметризованные тесты;
- `@ValueSource`;
- `@CsvSource`;
- `@CsvFileSource`;
- `@MethodSource`;
- `Arguments`;
- теги тестов через `@Tag`;
- пользовательские названия тестов через `@DisplayName`.

Также в проекте есть небольшой учебный пример `MiniJUnit`, который показывает, как с помощью рефлексии можно найти и запустить методы с аннотацией `@Test`.

### UI-автоматизация с Selenide

В репозитории находятся примеры UI-тестов с использованием Selenide:

- открытие страниц;
- поиск элементов;
- заполнение текстовых полей;
- нажатие на кнопки;
- работа с выпадающими списками;
- выбор даты в календаре;
- загрузка файлов;
- выбор радиокнопок и чекбоксов;
- работа с коллекциями элементов;
- проверки через `shouldHave` и `shouldBe`;
- ожидание появления элементов;
- проверка текста и количества элементов.

### Page Object

Форма регистрации на DemoQA постепенно переработана с использованием паттерна Page Object.

Логика разделена на отдельные классы:

- страница регистрации;
- компонент календаря;
- модальное окно с результатами;
- базовый класс с настройками тестов.

Это позволяет отделить действия со страницей от самих тестовых сценариев и сделать код более читаемым и переиспользуемым.
